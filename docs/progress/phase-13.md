# 阶段 13：可复现诊断与质量边界复核

日期：2026-08-27
状态：工程完成，等待集中人工验收

## 本阶段交付

- 复核真实基线中两例严重伪影及 InSwapper 原始对齐、生成和贴回实现。
- 确认超近景失败主要发生在 128×128 生成核心，而非单纯颜色匹配或边缘羽化；现有关键点与身份指标仍不能可靠识别该问题。
- 没有用缩小遮罩、覆盖原眼睛或降低身份替换范围来伪装质量提升，保留候选版算法与人工放大质检门禁。
- 新增 `diagnose.cmd`，让非技术用户双击检查 Windows、项目环境、磁盘、端口、模型、ONNX 执行器、显卡与驱动。
- 诊断可导出结构化 JSON，明确排除图片、人脸数据、任务编号、用户名、计算机名和本机路径。
- 新增 `verify-install.cmd`，在空闲临时回环端口上完成模型完整哈希、生产前端、安全响应头、API 代理和干净退出验证，并导出可移交的最小证据。

## 决策

本轮不修改默认换脸算法。只有在冻结真实样本上完成逐例视觉对比，并证明身份、未选区域和失败样本同时改善后，新的融合或模型方案才可进入候选版。

## 仍需外部完成

- 在另一台干净 Windows 设备双击 `setup.cmd`、`diagnose.cmd` 与 `start.cmd`，完成一次授权图片换脸。
- 产品负责人集中视觉验收后，才可决定是否创建稳定版标签。
