# 阶段 4：原生精准换脸 MVP

状态：工程实现完成，纳入最终集中验收
完成日期：2026-08-26

## 冻结范围

- 默认产品启动使用本地 `native-research` 后端；测试可显式注入不加载模型的模拟后端。
- 身份编码使用官方 `buffalo_l` 中的 `w600k_r50.onnx`，身份替换使用官方 `inswapper_128.onnx`。
- 两个权重仅限个人学习和非商业研究，不进入 Git、安装包或自动下载流程。
- 每个真实任务都必须同时保存本次图像授权确认、研究模型限制确认、检测器 ID、两侧稳定人物 ID、后端 ID 与换脸模型 ID。
- 优先使用 CUDA；GPU 推理真实失败时销毁并以 CPU Provider 重建模型，结果元数据记录最终实际执行器，不允许把静默降级冒充 GPU 成功。

## 已完成

- 新增 `native-research` 可选依赖组，锁定 InsightFace 1.0.1、ONNX Runtime GPU 1.26.0 及对应 CUDA/cuDNN Python 运行库；排除重复的 CPU ORT 与普通 OpenCV 包。
- 在公开模型清单登记 InSwapper 与 ArcFace 的官方来源、角色、精确文件大小、SHA-256、非商业限制和独立下载策略。
- 模型首次加载前校验清单、角色、商业使用标志、项目内路径、大小与 SHA-256；缺失、损坏或被替换均拒绝执行。
- 实现惰性模型加载和进程内复用，避免每个任务重复初始化大模型；换脸推理串行化，符合单任务队列约束。
- Windows 下显式注册由 Python 包提供的 NVIDIA DLL 目录，并禁用 ONNX Runtime 自动执行器降级；GPU 推理异常时只允许代码可观察的 CPU 重建路径。
- 后端按任务保存的检测器重新检测两张图片，并以稳定人物 ID 精确恢复来源人物和目标人物；任何一侧无法复现都失败且不生成结果。
- 原生工作流节点冻结为文件校验、任务准备、身份替换、输出检查与安全导出；任务事件来自后端真实进度。
- 输出必须保持目标图长宽，写入应用版本、AI 编辑标记、后端、检测器、换脸模型、最终执行器、水印和 JPEG 质量元数据。
- 可见 AI 水印继续默认开启；关闭水印不会关闭不可见 AI 编辑元数据。
- 结果先写入固定暂存文件，验证格式、尺寸与必需元数据后原子发布；失败、取消和超时路径删除任务图片及不完整结果。
- 新增 `/api/v1/capabilities`，将“API 进程在线”与“真实模型文件已安装”分开报告；只返回布尔状态和通用执行器名称，不暴露显卡、用户名或本机路径。
- 前端只有在真实模型文件存在时才允许提交，顶部明确显示模型已安装或缺失；研究模型限制仍要求单独勾选。
- 真实模型冷启动任务超时从 120 秒调整为 300 秒，避免完整性校验和首次 GPU 图优化被误判为死锁。
- 新增完整 API 冒烟脚本：会话、CSRF、上传、检测、选脸、创建任务、排队、GPU 换脸、轮询、下载与能力复核全部使用产品接口。

## 本机验证快照

- 目标环境：Windows、Python 3.14.6、NVIDIA RTX 5060 Laptop GPU。
- 实际完整 API 演练使用 SCRFD 检测、ArcFace 身份编码与 InSwapper 身份替换，任务成功，能力接口在推理后报告 `cuda`。
- 首次 YuNet 演练在困难来源图上返回无人脸并正确停止，没有误选人物或产生伪结果；改用此前已验证召回率更高的 SCRFD 后完成同一链路。
- 输出人工检查：目标姿态、身体、钢琴和背景保持，选中人物面部身份发生可见改变，图片完整显示，右下角存在默认 AI 编辑水印。
- 本快照证明目标设备路径可运行，不构成跨设备速度、身份准确率、公平性或商业可用性承诺。

## 自动化门禁

- 覆盖真实后端成功输出、所选人物无法复现、研究许可证缺失、模型字段缺失、GPU 推理失败后显式 CPU 重建、模型文件快速就绪检查及能力接口契约。
- 阶段提交前执行 Ruff、格式检查、Mypy、Pytest 与覆盖率、公开仓库扫描、前端检查、生产构建、隔离端口前后端联调和 Git 差异检查。
