# 发布、更新与回滚流程

## 发布门禁

稳定版标签只能在以下条件全部满足后创建：

1. `scripts/check.ps1` 在干净工作区通过。
2. 当前文件与完整 Git 历史资产扫描均通过。
3. GitHub Actions 的 Windows 质量门通过。
4. `scripts/diagnose.ps1 -FullModelHash` 在目标设备无 FAIL。
5. 产品负责人完成最终 UI、单脸、多脸、PNG、JPEG、水印开关、取消、清理和真实结果视觉验收。
6. 独立用户在干净 Windows 设备按用户手册完成安装与一次换脸。
7. 许可证清单没有未解释的默认依赖、模型或测试素材。

## 候选版

当前代码版本为 `1.0.0rc2`，前端显示版本为 `1.0.0-rc.2`。候选版可以提交到 `main` 并接受检查，但不得创建稳定 `v1.0.0` 标签，也不得宣称商业可用或公网生产就绪。

## 稳定发布步骤

1. 根据最终验收结果修复问题并重新跑全部门禁。
2. 将 Python、前端和锁文件版本从候选号改为 `1.0.0`。
3. 把 `CHANGELOG.md` 的候选章节标记为发布日期。
4. 提交版本冻结变更并等待 GitHub Actions 通过。
5. 创建带说明的签名标签 `v1.0.0`，再从该标签创建 GitHub Release。
6. Release 只包含源码与文档；不得附带模型、人脸素材、结果、运行数据库或本机日志。

## 更新

```powershell
git pull --ff-only origin main
.\setup.cmd
```

更新前下载或清除仍需处理的本地结果。不要在含未提交个人改动时强行覆盖。

## 回滚

先停止应用并备份确实需要保留的非敏感代码改动，然后从已知标签创建回滚分支：

```powershell
git switch -c rollback/v1.0.0 v1.0.0
.\setup.cmd
```

禁止用 `git reset --hard` 作为普通回滚说明。数据库或运行文件不承诺向后兼容；它们只含临时任务，升级或回滚前应从页面清除。
