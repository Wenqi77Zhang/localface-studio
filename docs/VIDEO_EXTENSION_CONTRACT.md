# 视频扩展接口冻结 v1

状态：接口预留完成，视频处理尚未实现

契约版本：1.0
目标版本：LocalFace Studio v2

## 为什么现在只冻结接口

单张图片产品必须先稳定，不能为了展示“视频功能”而把逐帧循环伪装成可用产品。真正的视频换脸还需要人物跨帧跟踪、时间一致性、音频复用、编码、断点恢复、长任务资源治理和新的人工验收。因此，v1 只建立不会破坏图片任务的独立端口。

## 已冻结的边界

| 接口 | 责任 | 隐私约束 |
| --- | --- | --- |
| `VideoFrame` | 帧序号、时间戳和 H×W×3 BGR 像素 | 不持久化到任务数据库 |
| `FrameSource` | 按时间顺序异步解码帧 | 容器路径不进入业务事件 |
| `FaceTracker` | 把相邻帧检测关联为任务内 track ID | track 仅在任务内有效，不是身份库 |
| `TemporalConsistencyProcessor` | 基于上一结果稳定当前选中人物 | 不得修改时间戳或未选人物 |
| `AudioMuxer` | 把已授权来源音频复用到最终视频 | 不做语音识别或说话人识别 |
| `VideoCheckpointStore` | 保存下一帧和已完成片段标识 | 明确禁止身份向量、帧像素和绝对路径 |
| `VideoWorkflowBackend` | 独立的视频长任务入口 | 不改变现有图片 `WorkflowBackend` 契约 |

对应代码位于 `src/localface_studio/application/video_contracts.py`，并有结构和隐私不变量测试。

## v2 必须新增的验证

1. 同一选中人物在遮挡、转身、出画和重新进入时不能错绑其他人物。
2. 每帧未选区域变化、身份相似度和闪烁指标必须同时报告，自动指标仍不能代替盲评。
3. 取消、崩溃和磁盘不足时，片段、帧缓存、音频缓存和 checkpoint 均进入清理。
4. 断点恢复必须核对输入摘要、工作流版本、模型哈希和上一片段完整性。
5. 音视频时长、帧率、时间基和同步误差必须有明确容差。
6. 显存、内存、磁盘和编码器资源必须设置预算，不能让长视频阻塞图片任务而无提示。
7. 输出继续保留可见水印默认值和不可关闭的 AI 编辑元数据。

## 明确非目标

- v1 页面不接受视频上传，也不显示虚假的“即将支持”按钮。
- 不做实时摄像头、直播换脸、多人批量替换、声音克隆或身份库。
- 不因已有接口就声称视频已可用、已测试或已取得模型/编解码器商业许可。
