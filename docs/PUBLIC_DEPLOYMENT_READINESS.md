# 公网部署就绪门禁

状态：**阻止公网推理服务部署；独立静态展示页已发布**
更新时间：2026-10-30

## 先区分三种交付

| 交付范围 | 当前判断 | 最近的缺口 |
| --- | --- | --- |
| 本机非商业研究演示、屏幕共享 | 有真实处理链，可继续验收 | 三组授权照片的完整结果与视觉接受结论、演示脚本及失败备用方案 |
| 公网静态介绍页，不接收上传 | 2026-10-30 已独立发布；当前定位为招聘/技术评审工程案例，见[展示版 v2](releases/showcase-v2.md) | 仅架构示意与脱敏汇总；真人结果图库和演示录像仍待展示授权，不得称为在线换脸 |
| 受邀在线试用或公开注册处理照片 | 尚未就绪 | 完整模型许可、身份与权限、限流与配额、运维、内容安全及合规 |

当前浏览器匿名会话已实现对象访问隔离，但不等于用户账户。当前队列单进程串行处理、每会话最多三个未完成任务；这不是已经验证的多用户容量或公平调度方案。配置仍硬性限制回环地址，Cookie 为本地 HTTP 设置，不能照搬到公网。

## 为什么当前不能直接上线

当前服务处理可识别人脸，属于高敏感度影像和生物特征相关场景；同时默认真实后端依赖非商业研究权重。把现有回环服务直接开放公网会绕过已冻结的许可证、隐私和滥用防护边界。因此“能启动公网端口”不等于“可以安全上线”。

## 生产上线前必须全部完成

1. 核验完整模型链，包括 ArcFace、InSwapper / AlphaFace 和所选检测器；取得覆盖拟部署用途的可审计授权，或替换为许可证兼容的模型与训练数据。只把 SCRFD 换成 YuNet 不会解除换脸模型和身份编码模型的限制。免费或受邀试用不自动等于非商业研究。
2. 增加真实账户、强认证、会话撤销、逐用户对象级授权和存储隔离。
3. 增加上传与任务速率限制、配额、排队、公平调度和成本上限。
4. 建立未成年人、敏感场景、非自愿亲密影像、冒充欺诈和名人滥用政策及举报处置。
5. 建立用户删除、保留期限、审计日志、数据出口、备份和事件响应流程。
6. 使用 HTTPS、Secure Cookie、受信反向代理、密钥管理、恶意文件扫描和网络分段。
7. 完成目标地区的肖像权、合成媒体标识、生物特征信息和隐私法律审查。
8. 完成第三方渗透测试、依赖漏洞处置、容量压测、灾难恢复与运营值班。

2026-10-30 来源复核：[InsightFace 官方许可说明](https://github.com/deepinsight/insightface#license)区分 MIT 代码和非商业研究模型，并提供换脸及识别模型的授权联系方式；当前 AlphaFace 转换权重来源的[固定版本登记](https://github.com/facefusion/facefusion/blob/3.9.0/facefusion/processors/modules/face_swapper/core.py)标为 Non-Commercial。这里是工程发布门禁，不代替对具体使用场景的法律意见。

## 建议的未来架构

- 公网控制面：账户、授权、策略、配额、审计和任务元数据。
- 隔离处理面：每任务临时工作区、无共享身份向量、受控模型运行器和结果自动销毁。
- 对象存储：逐用户加密命名空间、短期签名下载、生命周期删除和不可公开列举。
- 内容安全面：上传前政策确认、处理前风险检查、结果标识和人工举报通道。

当前代码中的回环地址校验是故意设置的硬门禁。只有完成上述项目并建立独立生产配置后，才应新增公网入口；不得通过删除校验或绑定 `0.0.0.0` 临时绕过。

2026-10-30 复查未改变该判断：本地候选版可演示不代表公网服务已就绪。当前缺口不是只租一台服务器即可解决；先冻结展示版、受邀试用或公开服务的范围，再分别验收。视频不是单张照片第一版的上线前置要求。
