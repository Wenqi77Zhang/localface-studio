# 公网部署就绪门禁

状态：**阻止生产部署**  
更新时间：2026-08-27

## 为什么当前不能直接上线

当前服务处理可识别人脸，属于高敏感度影像和生物特征相关场景；同时默认真实后端依赖非商业研究权重。把现有回环服务直接开放公网会绕过已冻结的许可证、隐私和滥用防护边界。因此“能启动公网端口”不等于“可以安全上线”。

## 生产上线前必须全部完成

1. 替换 ArcFace、InSwapper、SCRFD 等受限权重，或提供可审计的商业授权与模型卡。
2. 增加真实账户、强认证、会话撤销、逐用户对象级授权和存储隔离。
3. 增加上传与任务速率限制、配额、排队、公平调度和成本上限。
4. 建立未成年人、敏感场景、非自愿亲密影像、冒充欺诈和名人滥用政策及举报处置。
5. 建立用户删除、保留期限、审计日志、数据出口、备份和事件响应流程。
6. 使用 HTTPS、Secure Cookie、受信反向代理、密钥管理、恶意文件扫描和网络分段。
7. 完成目标地区的肖像权、合成媒体标识、生物特征信息和隐私法律审查。
8. 完成第三方渗透测试、依赖漏洞处置、容量压测、灾难恢复与运营值班。

## 建议的未来架构

- 公网控制面：账户、授权、策略、配额、审计和任务元数据。
- 隔离处理面：每任务临时工作区、无共享身份向量、受控模型运行器和结果自动销毁。
- 对象存储：逐用户加密命名空间、短期签名下载、生命周期删除和不可公开列举。
- 内容安全面：上传前政策确认、处理前风险检查、结果标识和人工举报通道。

当前代码中的回环地址校验是故意设置的硬门禁。只有完成上述项目并建立独立生产配置后，才应新增公网入口；不得通过删除校验或绑定 `0.0.0.0` 临时绕过。
